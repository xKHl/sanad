# Sanad — project instructions for coding agents

Sanad (سند) is a clinical decision-support **prototype** for a fictional outpatient clinic, built for a technical selection challenge judged by a hospital research unit (deadline Thursday 8 October 2026). A clinician enters a short de-identified scenario; the app returns (1) a structured case summary, (2) important missing information, (3) a next-step checklist for clinician review, (4) urgent red-flag warnings.

## Source of truth

- `docs/SPEC.md` — product and technical spec. Read the relevant section before changing code. If code and spec disagree, the spec wins until it is updated.
- `docs/PROGRESS.md` — running log. Read it first; update it when a piece of work is done.
- `docs/SAFETY.md`, `docs/EVALUATION.md` — safety card and evaluation report (the report is generated by `npm run eval`).

## Non-negotiables (safety)

1. Deterministic safety checks (`src/lib/safety`) run on every request and render first. The model can never remove, hide or downgrade a rule red flag.
2. Clinical thresholds, rule logic and wording come only from SPEC §5. Never invent clinical logic; if something looks clinically wrong, stop and ask.
3. Any change to clinical logic updates SPEC §5, the tests and `RULES_VERSION` in the same commit.
4. Decision-support language only ("Consider…", "Evaluate for…"). No diagnoses stated as fact. No medication doses, routes or frequencies.
5. Every AI fact and AI red flag carries a verbatim quote that code verifies (`src/lib/pipeline/grounding.ts`). Unverified items are marked; AI flags without a verified quote are dropped.
6. Identifiers are redacted before the safety layer and before any model call. Never log case text; log metadata only.
7. API keys live only in server environment variables. Nothing in `src/lib/ai` is imported by client components.
8. If the AI fails, the API returns 200 with `ai: null`, `aiError`, and the full safety findings.
9. Synthetic data only. Never add realistic identifiers to fixtures.

## Stack and commands

Next.js 16 (App Router) · React 19 · TypeScript strict · Tailwind CSS 4 · Vercel AI SDK 7 + Zod 4 · Vitest · tsx · npm.

```bash
npm run dev          # local server on http://localhost:3000
npm run build        # production build
npm run check        # typecheck + lint + tests (run after every meaningful change)
npm run eval         # evaluation report -> docs/EVALUATION.md (flags: --rules-only, --set dev|holdout|all, --runs N)
npm run record:demo  # record real model outputs for the sample cases (re-run when PROMPT_VERSION changes)
```

Library APIs changed recently: check the installed version and its docs before using an API. AI SDK 7 structured output is `generateText({ output: Output.object({ schema }) })` and the result is in `output`.

## Architecture map

```text
src/lib/safety/    pure, isomorphic, deterministic: text, phi, vitals, lexicon, negation, concepts, news2, rules, required-info, index
src/lib/ai/        server-only: schema, prompt, model (provider resolution), analyze, recordings
src/lib/pipeline/  analyze-case (orchestrator), grounding, merge, types
src/lib/export/    clinical note formatter
src/app/api/       analyze, status, lab route handlers
src/components/    UI (workspace, scenario, results)
src/data/          cases (dev + holdout), recordings.json
scripts/           eval.ts, record-demo.ts
```

- `src/lib/safety` must not use Node-only APIs, network or I/O: it also runs in the browser.
- Import `server-only` only in route handlers (Vitest aliases it to an empty module).

## Conventions

- TypeScript strict + `noUncheckedIndexedAccess`; no `any`; Zod at every boundary.
- Kebab-case file names, named exports; logic in `src/lib`, components presentational.
- Tests colocated as `*.test.ts`, table-driven where possible. Never weaken, skip or delete a test to make it pass.
- No new runtime dependency without a reason recorded in `docs/PROGRESS.md`.
- Conventional commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`).
